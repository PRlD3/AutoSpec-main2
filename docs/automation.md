# 自动运行说明

Trae 的安全策略可能要求对会修改文件、调用网络、执行外部程序或推送 Git 的操作进行确认。当前对话中不能通过项目文件永久关闭这些确认，也不建议绕过安全控制。

可以采用以下方式减少重复确认：

1. 把重复操作封装成项目脚本，例如 `python scripts/analyze_mbpp.py ...`、`python scripts/mbpp_to_c.py ...` 和 `python scripts/run_autospec.py ...`。
2. 先明确授权一次完整任务的范围，包括允许修改的目录、是否允许网络/API、是否允许 Git push、最大运行时间和停止条件。
3. 将纯本地、可重复、无破坏性的检查放入一个入口脚本；把 GitHub 推送、外部 API 调用和删除操作单独保留为需要确认的步骤。
4. 使用 CI 工作流执行无人值守任务。CI 中通过 GitHub Secrets 注入 API Key，不把密钥写进仓库；推送和发布使用最小权限的 token。
5. 对长任务使用固定输入目录、固定输出目录和日志文件，支持断点续跑，避免重复调用模型和重复覆盖结果。

不应把 API Key 放入命令行参数、脚本、日志、JSON 数据集或提交历史。自动运行前应先验证环境版本和磁盘空间，自动运行后检查退出码、结果文件数量和 Git diff。
