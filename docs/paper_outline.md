# 论文写作素材提纲

## 研究问题

- 如何将动态类型 Python 函数转换为具有明确内存和边界语义的 C 程序？
- 如何区分转换损失与形式化验证工具能力不足？
- 如何利用测试、一致性检查和 Frama-C 形成可复现的证据链？

## 方法贡献

- 面向 MBPP 的数据规范化和可追溯记录模型。
- 基于 AST 和类型/契约推断的分层转换工作流。
- 显式容器表示与 Python 语义运行时库。
- Python-C 差分测试和 Frama-C/AutoSpec 联合验证。
- 面向失败原因的分类统计，而不是单一通过率。

## 实验指标

- 数据集覆盖率和语言特性覆盖率。
- 解析成功率、类型推断成功率、C 编译率。
- 固定测试一致率、随机差分一致率。
- 未定义行为检测率和形式化证明率。
- AutoSpec 成功率、超时率、环境失败率和平均证明时间。

## 结果解释

翻译损失表示 Python 与 C 的行为在同一输入上不一致，或 C 表示无法保留必要语义。工具不足表示转换后的 C 已通过编译和差分测试，但 Frama-C、证明器、模型接口或运行环境未能完成验证。两类失败必须分别统计、分别抽样，并报告判定依据。
