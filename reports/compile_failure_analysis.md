# C 编译失败分析

## 基线

P0 路径修复后生成 67 个 C 文件，其中 40 个通过 GCC 编译，27 个编译失败。失败文件为：

`Mbpp_19.c`、`Mbpp_227.c`、`Mbpp_264.c`、`Mbpp_267.c`、`Mbpp_281.c`、`Mbpp_309.c`、`Mbpp_392.c`、`Mbpp_404.c`、`Mbpp_457.c`、`Mbpp_463.c`、`Mbpp_472.c`、`Mbpp_476.c`、`Mbpp_479.c`、`Mbpp_558.c`、`Mbpp_562.c`、`Mbpp_567.c`、`Mbpp_581.c`、`Mbpp_588.c`、`Mbpp_597.c`、`Mbpp_641.c`、`Mbpp_69.c`、`Mbpp_751.c`、`Mbpp_760.c`、`Mbpp_769.c`、`Mbpp_777.c`、`Mbpp_798.c`、`Mbpp_805.c`。

原始编译日志和结构化数据位于 `output/compile_analysis/` 与 `reports/compile_failures_analysis.json`。该轮统计使用 `gcc -std=c11 -Wall -Wextra -pedantic -c`，只检查编译，不执行测试。

## 主要错误类别

### 1. 未实现的 Python 内置函数或库语义

代表错误包括：

- `set(arraynums).length`
- `min(a, b, c)` 和 `max(a, b)` 被直接输出为不存在的 C 函数
- `int(...)` 被输出为 C 函数调用
- 其他未建模调用直接使用 Python 函数名

这是当前最有价值的修复方向。转换器不能对任意 Python 调用直接生成同名 C 调用，必须使用白名单和参数数量检查。`min/max` 应生成 C 辅助函数或嵌套比较；`int` 应转换为明确的整数语义；`set` 需要单独的数据表示和去重实现。

### 2. 列表类型推断错误

代表任务 `Mbpp_457.c` 将嵌套列表错误地当成 `IntList` 的整数数组，导致：

- `int Find_Min(int lst)` 参数类型错误；
- `make_int_list` 被嵌套用于构造 `int` 数组；
- `min_int_list` 处理的应该是嵌套列表而不是整数列表；
- 断言中出现嵌套 `IntList` 与整数比较。

这不是单个 C 语法问题，而是类型系统缺失。当前 `IntList` 只能表示一维整数列表，遇到列表元素是列表时必须拒绝转换，或引入 `IntListList` 二维表示；不能静默生成错误 C。

### 3. 变量作用域和重复声明错误

代表任务 `Mbpp_264.c`：

- `d_age` 在条件分支中声明；
- 后续分支又使用同名变量但超出声明作用域；
- 生成 C 中出现未声明变量。

赋值转换必须先进行函数级符号表分析，识别变量是否在多个分支使用，并在公共作用域声明，再在分支中赋值。不能仅根据遇到的第一条 AST 赋值语句决定 C 声明位置。

### 4. Python 类型转换和二元运算不安全

代表任务 `Mbpp_267.c`：

```c
return int(((n * (((4 * n) * n) - 1)) / 3));
```

C 中 `int` 不是可调用函数。类似 `pow`、浮点转整数、位运算和幂运算都需要显式规则，不能通过通用函数调用回退。

### 5. 测试断言类型不匹配

部分生成文件的函数返回值或测试输入包含嵌套列表、元组或其他容器，但 harness 仍按一维 `IntList` 或整数生成。即使函数主体能够编译，测试 harness 也可能无法编译。

测试翻译必须使用与函数参数和返回值一致的类型信息；无法表示的测试应分类为 `test_translation_failure`，不能生成不合法的 C 断言。

## 修复顺序

### P1-1：禁止任意调用直通 C

建立调用白名单：

- `abs(int)`
- `sum(IntList)`
- `min(IntList)`、`max(IntList)`
- `min(int, int)`、`max(int, int)` 及可控数量的参数
- `len(IntList)`
- `sorted(IntList)`

对 `int`、`set`、`heapq`、`math` 等未实现调用直接给出结构化转换失败，避免产生“看似生成成功、实际无法编译”的文件。

### P1-2：修复函数级符号表

在生成 C 之前收集所有变量的赋值、使用和候选类型，统一决定声明位置和类型。重点覆盖条件分支、循环和列表变量。

### P1-3：增加显式类型检查

当前转换器只支持一维整数列表。遇到嵌套列表、字符串、元组、字典或混合类型时，应报告 `unsupported_type`，而不是套用 `IntList`。

### P1-4：修复测试 harness 类型生成

测试输入需要从 Python AST 转换为 C 表达式，并与函数签名一致。对于当前不支持的返回类型和嵌套容器，保留失败原因并跳过 C 编译阶段。

## 当前结论

这 27 个编译失败文件主要不是 GCC 或环境问题，而是转换器生成了不符合 C 类型和调用规则的代码。下一步优先修复调用白名单、函数级符号表和类型拒绝策略。修复目标不是让所有文件“勉强编译”，而是减少错误代码生成，确保每个生成成功的文件都具备明确的 C 类型语义。
