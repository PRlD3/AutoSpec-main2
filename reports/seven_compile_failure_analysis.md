# 剩余编译失败分析

## 复现结果

使用当前提交重新生成并编译全部 399 条记录后，实际结果为：

```text
生成 C 文件：54
GCC 编译失败：1
```

失败文件为 `Mbpp_798.c`。此前报告中的 7 个失败文件来自修复函数参数重复声明之前的旧产物，不能继续作为当前版本的失败基线。

## Mbpp_798

生成的函数为：

```c
int _sum(int arr) {
    return sum_int_list(arr);
}
```

测试调用为：

```c
_sum(make_int_list((int[]){1, 2, 3}, 3))
```

GCC 错误指向 `sum_int_list(arr)` 的参数类型。根因是列表参数推断不完整：转换器目前只在下标、`len`、`append` 或 `for ... in list` 等语法中识别列表参数，但 `_sum` 只通过 `sum(arr)` 使用列表。因此函数签名错误地生成了 `int arr`，而 `sum_int_list` 要求 `IntList`。

## 根因分类

| 根因 | 当前数量 | 结论 |
|---|---:|---|
| 列表参数推断遗漏 `sum/min/max/sorted` | 1 | 当前唯一可复现编译失败 |
| 旧版本参数重复声明 | 0 | 已修复，旧 7 条不再属于当前基线 |
| 其他 GCC 编译失败 | 0 | 当前版本未复现 |

## 修复建议

在函数参数类型推断中，将单参数的 `sum`、`min`、`max`、`sorted` 调用加入列表使用点；测试参数中的列表字面量也应参与签名推断。修复后重新生成 `Mbpp_798.c`，应得到 `IntList arr` 并通过 GCC 编译。

## 质量结论

当前应将“编译失败文件数”以每次重新生成的产物为准，不复用旧目录和旧日志。测试报告必须保存转换器提交号、生成目录、编译命令和失败文件列表，以避免修复后仍把历史错误计入当前统计。
