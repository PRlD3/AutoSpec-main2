# ACSL 内存分配包装函数报告

## 新增包装函数

生成的 C 文件现在包含：

- `checked_malloc(size_t size)`：调用 `malloc`，检测空指针并在失败时终止。
- `checked_realloc(void *ptr, size_t old_size, size_t new_size)`：调用 `realloc`，检测空指针并在失败时终止；旧容量用于描述原内存区的有效范围。

两个函数均带有 ACSL 前置条件和后置条件，调用点不再直接调用裸 `malloc` 或 `realloc`。

## 验证结果

以重新生成的 `Mbpp_101.c` 为代表样例：

- GCC C11 编译通过。
- C 运行时断言通过。
- Frama-C/WP 解析通过。
- Z3 生成并处理 52 个目标。
- `24 / 52` 个目标证明通过。
- 工具没有因 ACSL 语法或调用包装函数而中止。

相比上一版直接使用 `malloc/realloc` 的 `21 / 38`，目标数量增加是因为包装函数自身的分配后置条件、失败分支和调用契约也进入了证明范围。因此证明比例不能直接作为单调质量指标。

## 当前未决问题

Frama-C 仍对 C 标准库 `malloc/realloc` 的底层分配、释放性和对齐性质报告模型限制，包装函数无法凭自身代码消除这些外部模型假设。下一步需要为分配函数建立项目级 axiomatic/model，或使用 Frama-C 标准库提供的更精确内存模型；同时补充 `assigns`、`reads`/`\from` 和扩容循环不变量。

## 结果边界

本轮证明了包装函数的调用路径可被 Frama-C/WP 解析，并显式处理了空指针失败路径；这不等同于所有动态内存安全性质已经完全证明。
