# 转换器回归分析

## 结果

当前版本重新运行 MBPP 399 条记录：

| 阶段 | 数量 |
|---|---:|
| 总记录 | 399 |
| C 生成成功 | 54 |
| 转换阶段失败 | 345 |
| GCC 编译成功 | 47 |
| GCC 编译失败 | 7 |

与前一轮 67 个生成、40 个编译成功相比，生成数量减少是调用白名单和类型拒绝策略生效的结果；编译成功数量从 40 增至 47，说明生成代码质量提高。

## 失败原因

转换阶段首个原因的粗粒度统计为：

- 不支持的表达式：109
- 类型或列表相关：59
- 不支持的函数调用：59
- 不支持的语句：41
- 字符串相关：22
- 不支持的二元运算：20
- 其他：35

这些类别可能重叠，不能相加作为互斥统计。原始明细位于 `reports/regression2_failures.jsonl`。

## 编译失败

修复参数重复声明后，剩余 7 个生成文件仍未通过 GCC。编译明细位于 `reports/regression2_compile_failures.json`。它们主要是生成器辅助函数、测试 harness 或尚未完整建模的表达式问题，应逐项修复，不应直接把编译失败计入转换成功。

## 结论

本轮修复的主要效果是提高转换结果的可信度：未实现调用不再伪装成 C 调用，嵌套列表不再错误地使用 `IntList`，函数参数不再被重复声明。下一步应分析剩余 7 个编译错误，并完善失败记录的阶段字段，然后再实现新的 Python 语义。
