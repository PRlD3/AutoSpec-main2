# 转换器回归分析

## 结果

当前版本重新运行 MBPP 399 条记录：

| 阶段 | 数量 |
|---|---:|
| 总记录 | 399 |
| C 生成成功 | 54 |
| 转换阶段失败 | 345 |
| GCC 编译成功 | 49 |
| GCC 编译失败 | 5 |

本轮增加了 `sum`、`min`、`max`、`sorted` 单参数调用的列表参数推断。生成文件从 54 个增至 54 个，其中 `Mbpp_798.c` 的签名已从 `int _sum(int arr)` 修正为 `int _sum(IntList arr)`。GCC 编译结果为 49 个通过、5 个失败；新增列表类型信息暴露了列表真值判断、列表比较和列表拼接等尚未实现的语义，避免了将这些参数错误地当作整数。

## 失败原因

转换阶段首个原因的粗粒度统计为：

- 不支持的表达式：109
- 类型或列表相关：59
- 不支持的函数调用：59
- 不支持的语句：41
- 字符串相关：22
- 不支持的二元运算：20
- 其他：35

这些类别可能重叠，不能相加作为互斥统计。原始明细位于 `reports/regression2_failures.jsonl`。

## 编译失败

本轮剩余 5 个编译失败文件为 `Mbpp_463.c`、`Mbpp_476.c`、`Mbpp_567.c`、`Mbpp_597.c` 和 `Mbpp_69.c`。失败分别涉及列表上的 `!`、列表相等比较、列表拼接以及切片结果比较。它们属于尚未实现的列表语义，应在转换阶段显式拒绝，不能直接计入转换成功。

## 结论

本轮修复的主要效果是提高转换结果的可信度：列表内置函数的参数类型得到正确推断，`Mbpp_798.c` 已可通过 GCC；未实现调用不再伪装成 C 调用，嵌套列表不再错误地使用 `IntList`，函数参数不再被重复声明。下一步应将剩余 5 类列表语义加入转换阶段的显式拒绝规则，再继续扩展新的 Python 语义。
